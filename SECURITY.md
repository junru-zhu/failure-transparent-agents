# Security Policy

## Reporting a vulnerability

Please use GitHub's private security-advisory workflow for vulnerabilities in
the harness, release process, credential handling, or sanitization logic.
Avoid filing a public issue when a report could expose credentials or a
repeatable security weakness.

Do not include live API keys, AWS credentials, provider request IDs, private
execution-environment names, or employer data in a report or reproduction.

## Supported version

Security fixes target the latest code on the default branch and the latest
published release when practical.

The benchmark scenarios are synthetic. The repository must never require real
personal, financial, medical, employer, or confidential account data.
